## 如何基于代码资产细化（建议顺序）

1. **先审计，后改文档**：对照 `pilot/w1-trim` 代码核对你负责域的每一处表述——接口文档第 3 章已实现域的每个参数、枚举值都能在代码里找到落点（controller 注解 / Flyway 脚本 / 前端 api 层）；
2. **重点核对清单**：
   - 需求 §4 各域状态标注（已实现/设计中/规划）是否与代码一致；
   - 接口 §1.4 枚举表与 `constants/`、字典、后端实体取值一致；
   - 设计中域（第 4/5 章）的字段定义是否够你开工，缺什么直接在文档批注或 issue 提；
   - 演进路线 R-01~R-12 的验收口径是否可执行，不可执行就改口径（issue 说明理由）；
3. **细化权限**：V3 文档内直接修订（留修订模式或批注），不要另起 V3.1 文件；改完提交 PR，PR 描述写「文档影响：…」；
4. **纪律**：不引入封存线内容（docs/11 清单）；不写实公司/人物名；内部代号不进文档。
