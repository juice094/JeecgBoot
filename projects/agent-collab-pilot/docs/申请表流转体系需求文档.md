# 申请表流转体系需求文档

## 1. 背景与目标

日常申请（请假/报销/加班等）走轻量审批流，**不上 Flowable**。核心诉求：

| 主线 | 本质 | 典型场景 | 验收口径 |
|---|---|---|---|
| F 申请表流转 | 单据状态机 | 提交 → 按步骤审批 → 通过/驳回 | 流转合法、越权拦截、全程留痕可查 |

**目标**

- 显式状态字段 + 流转记录表，禁止隐式流转（issue #3 约束原文）。
- 审批操作强守卫：重复操作、越权审批、自审一律拒绝。
- 关键动作全量落审计，支持按单据追溯。

> 现状：接口已落地（jeecg-module-team，`/team/approval/**` + `/team/audit/list`）。本文随码维护。issue #3 合同对照：模板化申请成分按宿裁定延后（D-20261117-68），本期不做（§8）。

## 2. 范围界定

**本期包含**

- 提交申请（单据 + 审批步骤链）、单号生成。
- 待我审批查询（两步走，按登录人姓名匹配当前步骤）。
- 审批操作（通过/拒绝，多级步骤推进）。
- 步骤链查询、全量列表、详情。
- 审计追溯（提交/通过/拒绝全量留痕）。
- 仪表盘聚合的 team 侧待审计数。

**本期不包含**

- 表单模板表（JSON 配置化字段）：延后（D-20261117-68）。
- 撤销（cancel）/驳回后重提（resubmit）：产品语义待宿拍板。
- 人员选择器真实绑定：等 admin 线（issue #4/#5）导出接口。
- 审批人严格身份校验（approver_id 列）：待后续 Flyway 加列升级。

## 3. 角色与权限

| 角色 | 权限 |
|---|---|
| 申请人 | 提交申请；查看本人申请；不可审批本人单据 |
| 审批人 | 按步骤链顺序审批当前步骤（姓名匹配，弱校验） |
| 系统管理员 | 全量单据查询；审计日志查询 |
| Agent（系统身份） | 封存线（docs/11），本期不实施 |

## 4. 体系设计约束（需求侧可验收项）

### 4.1 分层与依赖

```text
接入方：OA 前端（RequestForm.vue / ApprovalCenter.vue）
   ↓
Controller 层 /team/approval/**
   ↓
Service 状态机：submit → requirePending → requireActionableStep（守卫）→ 步骤推进
   ↓
MyBatis-Plus + 事务（流转 + 审计同事务回滚）
   ↓
MySQL：team_approval / team_approval_step / team_audit_log
```

**必须满足的依赖规则**

1. 审批动作必须经守卫链：单据 pending → 当前步骤存在 → 步骤未操作 → 登录人匹配审批人 → 非申请人自审。
2. 步骤链只增不改写：已通过/已拒绝步骤不允许变更。
3. 每次 submit/approve/reject 同步写 `team_audit_log`（同事务）。
4. 申请人/审批人身份字段由服务端从登录态回填，不信任请求体。

### 4.2 数据所有权

| 表 | 唯一写者 | 读方式 |
|---|---|---|
| `team_approval` | team 模块 | 审批 API |
| `team_approval_step` | team 模块 | 步骤链 API |
| `team_audit_log` | team 模块（TeamAuditLogger 只追加） | 审计 API |

### 4.3 核心数据模型

**审批单（team_approval，V3.9.6_3）**

- `code` 单号（唯一，`OA-yyyyMMdd-NNN`）、`category`（申请类别）、`title`（必填）、`reason`。
- `status`（pending/approved/rejected）、`applicant_id` / `applicant_name`。
- `start_date` / `end_date`、`current_step`（当前待审步骤序号）。
- jeecg 四字段 + `sys_org_code` / `sys_tenant_id`。

**审批步骤（team_approval_step，V3.9.6_3）**

- `approval_id`、`step_no`（从 1 开始）、`approver_name`、`approver_role`。
- `action`（wait/approved/rejected）、`comment`、`acted_at`、`create_time`。

**状态机**

- `pending(currentStep=N)` → 当前步骤 approve → 末步 `approved` / 非末步 `currentStep=N+1`。
- 任一步 reject → 整单 `rejected`（终态）。
- 同步骤重复操作、自审、非本步骤审批人操作均非法。

### 4.4 DDL 约定

- 新表走 Flyway 脚本，编号在 V3.9.6_x 上顺延；jeecg 四字段必备。
- `team_approval` 唯一键 `uk_team_approval_code(code)`，索引 `(status)`。
- `team_approval_step` 索引 `(approval_id)`。

## 5. 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| F-1 | 提交申请：单据 + 步骤链，单号生成，申请人登录态回填 | P0 | 标题必填、startDate≤endDate、步骤非空、审批人非空；审计 SUBMIT |
| F-2 | 待我审批：两步走查询 | P0 | step 表 wait+登录人姓名 → 主表 pending + currentStep 匹配；分页 |
| F-3 | 审批通过：当前步骤推进，末步整单 approved | P0 | 守卫全通过才可操作；update_by 回填；审计 APPROVE（step:N 快照） |
| F-4 | 审批拒绝：整单 rejected | P0 | 守卫同上；审计 REJECT |
| F-5 | 步骤链/详情/全量列表查询 | P0 | steps 按 stepNo asc；list 支持 status/category/applicantId 过滤 |
| F-6 | 审计追溯 | P0 | /team/audit/list 按 bizType=approval/bizId 过滤，submit→approve 全链可查 |
| F-7 | 仪表盘待审计数 | P1 | /team/dashboard/summary 的 pendingApprovalCount（status=pending） |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 待我审批两步走均走索引（idx_step_approval），试点量级内存分页 |
| 可靠性 | 流转与审计同事务；单号生成试点级（高并发换 Redis 发号，代码已标 ponytail） |
| 安全 | 申请人/审批人服务端回填；越权/自审/重复操作强拦截 |
| 兼容 | JeecgBoot 单体：Java 17 + Spring Boot 4.1 + MyBatis-Plus（jakarta）；Knife4j 注解随码 |
| 审计 | from/to 用 step:N 快照口径；审批意见进 detail/comment |

## 7. 迭代计划

| 期 | 交付内容 | 状态 |
|---|---|---|
| 一期 | F-1、F-3~F-6（提交 + 审批操作 + 守卫 + 审计 + 查询） | ✅ 已落地（2026-11-17） |
| 二期 | F-2、F-7（待我审批两步走 + 仪表盘计数） | ✅ 已落地（2026-11-17） |
| 三期 | 表单模板、resubmit/cancel、approver_id 严格化（按需拍板） | 挂起 |

## 8. 已知限制与挂起项

1. 越权校验按审批人姓名比对（step 表只有 approver_name），重名者互见待办/可互批；严格化需加 approver_id 列。
2. rejected 为终态，无重提；cancel 未定义——均待宿拍板。
3. 申请类别为自由文本，模板化延后（D-20261117-68）。
4. F-09 最小权限补丁整体处理中，本体系未局部加按钮级权限。

## 9. 验收清单

1. 提交：缺 steps 报错；startDate>endDate 报错；成功后 steps 全部 wait、currentStep=1。
2. 守卫：申请人自审被拒；非当前步骤审批人被拒；同步骤双击第二次被拒。
3. 流转：两步链首步通过后 currentStep=2；末步通过后 status=approved。
4. 拒绝：任一步 reject 整单 rejected，后续 approve 返回"当前状态 rejected"错误。
5. 待我审批：/todo 只含当前步骤匹配登录人姓名的 pending 单。
6. 审计：单据全生命周期在 /team/audit/list 可查（SUBMIT → APPROVE/REJECT，from/to 快照）。
