# 01 — 总体架构


## jeecg 删改清单

**保留**：`sys_user` / `sys_role` / `sys_permission` / 部门 / 数据字典 / 菜单权限体系。

**裁剪**：online 表单、报表、大屏、仪表盘等低代码组件——试点用不上，减少攻击面与维护成本。

**新增（手写，不走代码生成器）**：`im`、`agent-task`、`device`、`account`、`audit` 五个模块，仅挂入 jeecg 菜单/权限体系。消息热路径不允许生成器产物污染。

## 部署视图（试点）

单机 docker-compose：gateway、im-service、account-service、nacos、MySQL、Redis、浏览器池容器、worker。

**控制面/数据面分离设计**：网关与业务状态无本地磁盘依赖，浏览器池与 worker 可整体平移到其他节点，架构图不变。

## 安全边界

- 消息**内容**与**会话存储**：客户端侧（SQLCipher 加密）
- 用户**关系**、**设备准入状态**、审计**结果**（HMAC）：云端
- 服务器不掌握明文内容，但凭签名执行策略（如 audit 未通过的消息禁止路由进 AI 账号会话）
- 内网服务只监听 Tailscale 网卡（100.x），公网零暴露（noVNC/CDP/管理面板同规则）——安全组由服务商持有，不开任何公网入站端口
