# 19 — 需求文档：智能体团队的管理与开发机制

> 2026-11-17，juice094（周景潇）发起，Kimi Code（DSH agent-team 班组模式）起草。
> 依据：docs/11（方向裁决）、docs/13（团队上手指南）、ROADMAP、DSH `@deepseek-ai/dsh-experimental-agent-team-profile` v0.2.1-rc.4 实测能力。
> 本文档为个人需求与开发文档的入口文档；配套：docs/20（资产盘点与接入流转）、docs/21（开发文档）、docs/22（接口文档待办）。

## 一、背景与定位

DSH 已启用实验性 agent-team 组件（团队协作 / 团队工具 / 团队面板，均运行中），具备：Team Lead + 队友编制（roster 上限 8）、成员 inbox 消息、共享任务看板（认领制 + 阻塞依赖）、成员会话切换。本项目（团队协作效率工具）需要回答两个问题：

1. **研发侧**：三人团队（qingyanjunzi / Ym3699 / juice094）如何用 agent 班组机制提升本仓库的开发效率与质量——这是**过程工具**，不进产品、不进对外文档。
2. **产品侧**：团队协作效率工具本身是否要提供"智能体团队"能力——让平台用户可以创建 AI 智能体作为"团队成员"参与任务协作、审批、公告问答等业务流程线——这是**产品功能**，须走立项评审。

### 与封存线的边界（docs/11 红线，先声明防跑偏）

| 封存线（❌ 本文档不重启） | 本文档要做的事（✅） |
|---|---|
| 账号池生命周期、隔离浏览器批量登录 webAI | 平台内 airag 能力的产品化（对话/知识库/流程编排） |
| AI 会话采集与 session 复用（docs/08） | 智能体对**本项目业务数据**（任务/审批/公告）的受控读写 |
| Nacos agent 调度、agent_tasks 租约抢占（docs/04） | 轻量触发：事件驱动 + 人工确认节点，无抢占调度市场 |
| WSS 网关与设备准入（docs/01） | 不涉设备准入，走 JeecgBoot 现有 Shiro + JWT |

一句话区分：**封存线调度的是"外部 webAI 账号"，本文档管理的是"平台内 AI 能力与人机协作流"**。任何重启封存线内容的动作仍需技术总监重新拍板（docs/11 末节）。

## 二、目标与非目标

### 目标

- **G1（研发侧，立即生效）**：建立 agent 班组开发机制——Lead 编排 + 专项队友 + 共享任务看板，覆盖本仓库业务流转、前端、文档等工作线。
- **G2（资产侧，本周完成）**：盘点项目既有 agent 资产（airag 模块全部能力、提示词、流程编排、知识库），形成接入与流转方案（docs/20），回答"哪些直接复用、哪些包装、哪些新建"。
- **G3（产品侧，M4+ 立项）**：产出"智能体团队"产品功能的 PRD 级需求与开发文档（本文档 + docs/21），供技术总监评审排期。

### 非目标

- 不改 docs/11 封存裁决，不恢复账号池/浏览器池/会话采集任何子系统。
- 不替代三人人类分工与 issue 协作流（docs/13）；agent 队友编入 juice094 业务组，是人类能力的放大器而非替代。
- 产品侧智能体不做自主对外行动（发邮件、发公告）而无人工确认节点。

## 三、研发侧机制需求（G1，立即启动）

> 性质：开发过程约定，约束本仓库所有 agent 参与方；由 lead（编排 agent）执行，宿 review。

| 编号 | 需求 | 说明 |
|---|---|---|
| D1 | 班组编制 | Team Lead 一名 + 专项队友（首名：`bizflow-dev`，负责 jeecg-module-team 业务流转补全）。roster ≤ 8；长期不活跃的成员及时释放编制。 |
| D2 | 共享任务看板 | 工作项一律上板（`team_task_create`），认领制 + `blocked_by` 依赖；板上可见 owner。看板是**研发编排层**，与产品功能 `team_task` 业务表同名不同层，文档与讨论中必须带前缀区分（板任务 vs 业务任务）。 |
| D3 | inbox 即任务变更 | 成员必须读取 inbox；lead 经 `send_message` 派活/纠偏，成员每轮回报"结果 + 验证输出 + 读过/动过的文件清单"。 |
| D4 | git 纪律 | agent 队友不执行任何 git 写操作（不 commit/push），只改文件；宿统一 review 后按 docs/13 分支模型提交。人类成员仍按 feature 分支 + PR 流程。 |
| D5 | 工作面隔离 | 队友只改被授权的目录（如 `jeecg-module-team/**`、`jeecg-team-web/src/modules/business/**`）；宿主在途未提交文件列入禁区清单（当前：`jeecg-module-team/pom.xml`、`jeecg-team-web/src/layout/SidebarMenu.vue`）。 |
| D6 | 验证分级诚实 | 报告标注验证级别：静态 < 编译 < 单测 < 运行态；probe 不可达如实标"宿主侧"。 |
| D7 | 成本与上下文纪律 | 成员上下文随轮数累积，长成员=长账单；一次性散活用一次性子代理不占编制；异常消耗报宿。 |

**验收**：机制本身运行两周（至 2026-12-01），期间 agent 产出至少一个经宿 review 合入的业务功能 PR，且无越界改动、无 git 违规。

## 四、产品侧需求（G3，M4+ 评审排期）

> 前提：M3 业务基础功能（任务/审批/公告/审计）已落地；airag 资产盘点（docs/20）结论为"可复用为主"。以下需求为 PRD 级骨架，立项后细化。

### 4.1 用户场景

| 场景 | 描述 | 涉及的现有模块 |
|---|---|---|
| S1 审批预审 | 员工提交请假/报销单后，智能体先做单：字段完整性检查、历史同类单参考、预算科目建议，再给审批人一份预审摘要；审批权仍在人。 | team_approval + airag |
| S2 任务协作 | 任务创建时智能体给出拆解建议；被指派的智能体在截止前未完成的产出可被催办/升级提醒；任务归档时自动生成进展摘要。 | team_task |
| S3 Bug 分流 | Bug 提交后智能体按知识库做分类/疑似去重/优先级建议，维护人确认后进入流转。 | team_bug + 知识库 |
| S4 公告问答 | 团队成员对公告/制度文档的自然语言问答，RAG 引用可追溯。 | sys_notice + 知识库 |
| S5 日报聚合 | 每日下班前智能体汇总当日 team_task/team_bug/team_approval 变更，生成团队日报草稿，负责人确认后发布。 | 三表聚合 + 公告 |

### 4.2 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| P1 | **智能体档案**：名称、角色标签、能力标签、绑定模型（airag llm）、绑定知识库、提示词模板（airag prompts）、启停状态 | 高 |
| P2 | **团队编组**：智能体作为特殊"成员"编入项目组，参与任务指派/审批流转；权限继承 JeecgBoot RBAC（智能体身份 = 特殊 sys_user 或独立主体映射，立项时定） | 高 |
| P3 | **业务流程线编排**：以 airag AI 流程编排为引擎，定义 S1-S5 各流程线的节点图（触发 → 取数 → AI 节点 → 人工确认 → 写回 → 留痕） | 高 |
| P4 | **人机协作闭环**：所有写回业务表的节点前设人工确认；智能体输出与人工修改全程留痕，写入 M3 审计日志 | 高 |
| P5 | **运行观测**：流程运行记录（输入/输出/token 消耗/耗时）、失败重试与人工接管入口 | 中 |
| P6 | **渠道接入**：智能体能力以 Mattermost bot / 系统消息两种渠道触达成员 | 中 |
| P7 | **嵌入第三方**：沿用 airag Iframe 嵌入能力，把公告问答等场景输出给外部系统 | 低 |

### 4.3 非功能需求

- 安全：智能体对业务表的写操作全部走服务端 API + 数据权限拦截器，禁止直库写；提示词注入防护（输入边界校验）。
- 成本：每次流程运行记录 token 消耗，提供单智能体/单流程线月度成本视图。
- 可审计：P4 留痕为强制项，与 M3 审计日志同表体系。
- 密钥债：`airag_model.credential` 模型密钥明文存储为上游既有债（docs/20 §3.5），M4-α 启动前须完成脱敏审计并给出处置排期（接 jeecg 加密或 KMS）。

## 五、业务流程线编排建议

> 对应诉求"项目内 agent 管理与业务流程线编排"。编排三原则：**事件触发**（不引入调度市场）、**人工确认**（AI 建议、人来拍板）、**全程留痕**（衔接审计）。

### 5.1 建议编排的四条业务线

```
审批线：team_approval 提交(pending)
  → [触发] 状态变更事件
  → [取数] 单据字段 + 历史同类单 + 预算数据
  → [AI] airag 流程：预审摘要生成（P1 智能体）
  → [人工] 审批人看到摘要 → approve/reject（现有状态机不动）
  → [写回] 预审摘要存入审批单扩展字段 / 审计日志
  → [升级] 超时未审 → 智能体催办提醒（sys_message）

任务线：team_task 创建/指派
  → [AI] 拆解建议（创建时，可选采纳）
  → [人工] 任务执行（人做；智能体只做提醒与归档摘要）
  → [触发] 截止前 N 小时未完成
  → [AI] 生成进展摘要 + 催办消息

Bug 线：team_bug 提交(open)
  → [AI] 知识库分类 + 疑似重复检索 + 优先级建议
  → [人工] 维护人确认 → processing/resolved/closed（现有流转不动）

公告问答线：sys_notice / 制度文档 → 知识库
  → [AI] RAG 问答（引用溯源）
  → [人工] 无写回，纯查询；答不上转人工
```

### 5.2 编排落地方式

- **引擎**：airag AI 流程编排引擎为闭源构件（jeecg-aiflow-boot4 jar），本 fork 中 `/airag/flow/**` 管理端点不可用（docs/20 §3.1 已核实）。流程线 MVP **降级为"编排模板表 + 代码编排"**（每条业务线一个 Spring 编排器，模板表只存变量映射/确认策略/写回映射），不依赖闭源引擎；chatFlow 应用入口（`/sys/api/runAiragFlow`）仅作包装档备用。待画布编排需求确证后，评审自研编排器或等上游开放，再迁移。新增节点类型（人工确认/业务写回）诉求随之转为**编排器配置项**，不再依赖引擎扩展点。
- **触发**：MVP 用"业务事件 → 调用流程 API"的同步/半同步触发（jeecg 已有 Quartz 可补定时场景如 S5 日报）；不引入消息队列调度。
- **权限**：流程运行身份 = 触发人身份，数据权限随人；智能体跨人取数必须经授权节点。
