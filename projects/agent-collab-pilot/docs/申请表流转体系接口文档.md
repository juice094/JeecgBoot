# 申请表流转体系接口文档

> 本文档与已实现代码一致（jeecg-module-team，2026-11-17 落地）。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| REST Base Path | `/jeecg-boot/team` |
| 认证 | jeecg 登录态（`X-Access-Token` header，Shiro 校验） |
| 统一响应 | jeecg `Result<T>`：`{ "success": true, "code": 200, "message": "...", "result": {}, "timestamp": ... }`；业务错误 `Result.error("文案")` |
| 分页参数 | `pageNo`（默认 1）、`pageSize`（默认 10），返回 `IPage`（records/total/pages/current） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（GMT+8）；startDate/endDate 为 `yyyy-MM-dd` |
| 操作留痕 | 写操作带 `@AutoLog`；submit/approve/reject 额外落 `team_audit_log` |

## 2. 提交申请

| 项 | 说明 |
|---|---|
| POST | `/team/approval/submit` |

**请求体**

```json
{
  "approval": {
    "category": "加班申请",
    "title": "周六上线支持",
    "reason": "版本发布窗口值守",
    "startDate": "2026-11-22",
    "endDate": "2026-11-22"
  },
  "steps": [
    { "approverName": "贺致远", "approverRole": "部门主管" },
    { "approverName": "黄茜茜", "approverRole": "副总经理" }
  ]
}
```

**规则**：steps 非空必填（模板成分延后，D-20261117-68）；applicantId/applicantName/createBy 服务端从登录态回填，请求体传入无效；startDate ≤ endDate；每步 approverName 非空。

**响应**

```json
{ "success": true, "code": 200, "result": { "id": "ap1", "code": "OA-20261117-001",
  "status": "pending", "currentStep": 1, "applicantName": "张三" } }
```

**失败文案**：`事项标题不能为空`、`开始日期不能晚于结束日期: ...`、`审批流程至少需要一个步骤`、`审批步骤缺少审批人: 第 N 步`

## 3. 待我审批

| 项 | 说明 |
|---|---|
| GET | `/team/approval/todo?pageNo=&pageSize=` |
| 口径 | 两步走：step 表 action='wait' + approver_name=登录人姓名 → 主表 id 命中且 status=pending → currentStep 与 wait 步骤序号内存匹配；create_time desc |

**已知限制**：步骤表只冗余审批人姓名，重名者会互相看到对方待办；严格身份校验待 team_approval_step 加 approver_id 列后升级（与越权校验同一立项）。

**响应**

```json
{
  "success": true, "code": 200,
  "result": { "total": 2, "records": [
    { "id": "ap1", "code": "OA-20261117-001", "category": "加班申请", "title": "周六上线支持",
      "applicantName": "张三", "status": "pending", "currentStep": 1,
      "createTime": "2026-11-17 10:00:00" }
  ]}
}
```

## 4. 审批操作

### 4.1 通过当前步骤

| 项 | 说明 |
|---|---|
| POST | `/team/approval/approve?id=<id>&comment=<可选>` |
| 效果 | 当前步骤置 approved（记意见/时间）；末步整单 approved，否则 currentStep+1 |

### 4.2 拒绝当前步骤

| 项 | 说明 |
|---|---|
| POST | `/team/approval/reject?id=<id>&comment=<可选>` |
| 效果 | 当前步骤置 rejected，整单 rejected（终态） |

**守卫（approve/reject 共用，失败返回上下文文案）**

| 守卫 | 失败文案示例 |
|---|---|
| 单据存在且 pending | `审批单不存在: id=...` / `审批单当前状态为 rejected，不可审批: code=...` |
| 当前步骤未被操作 | `当前步骤已被操作，禁止重复审批: code=..., stepNo=1, action=approved` |
| 登录人=当前步骤审批人 | `越权审批: 当前步骤审批人为 贺致远，登录人为 张三（code=...）` |
| 登录人≠申请人 | `申请人不能审批自己的单据: code=...` |

**审计口径**：APPROVE/REJECT，from/to 用 `step:N` 快照（末步通过 to=approved，拒绝 to=rejected），comment 入 detail。

## 5. 查询接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/team/approval/list` | QueryGenerator 分页；过滤 status/category/applicantId/title 等；排序 create_time desc |
| GET | `/team/approval/my（无此端点）` | "我的申请"用 /list + applicantId=登录人 id 过滤 |
| GET | `/team/approval/steps?id=` | 步骤链，stepNo asc（wait/approved/rejected + comment + actedAt） |
| GET | `/team/approval/queryById?id=` | 单据详情 |

**步骤链响应**

```json
{ "success": true, "code": 200, "result": [
  { "stepNo": 1, "approverName": "贺致远", "approverRole": "部门主管",
    "action": "approved", "comment": "同意", "actedAt": "2026-11-17 11:00:00" },
  { "stepNo": 2, "approverName": "黄茜茜", "approverRole": "副总经理",
    "action": "wait", "comment": null, "actedAt": null }
]}
```

## 6. 仪表盘聚合（共用）

| 项 | 说明 |
|---|---|
| GET | `/team/dashboard/summary` |
| 响应 | `{ "pendingApprovalCount": 3, "myUnfinishedTaskCount": 5, "openBugCount": 2, "unreadNoticeCount": 4, "latestNotices": [{ "id": "...", "titile": "...", "sender": "...", "sendTime": "..." }] }` |
| team 口径 | 待审审批数=status=pending；未完成任务=assignee=me 且 in todo,doing；未关闭 Bug=in open/processing/resolved |
| sys 口径（D-72 宿裁授权例外，2026-11-17 落地） | 未读数=`sys_announcement_send` 中 user_id=当前登录人且 read_flag=0 的行数；最新公告=`sys_announcement` del_flag='0' 且 send_status='1'（已发布）按 send_time 倒序前 5 条（titile 为上游既有拼写） |
| 留痕 | team 域直读 sys 表仅此一处；ISysBaseAPI 无现成计数方法；与 F-10 无关（sys_sms 为推送日志，无未读语义） |

## 7. 审计追溯

| 项 | 说明 |
|---|---|
| GET | `/team/audit/list?pageNo=&pageSize=&bizType=approval&action=&bizId=` |
| 过滤 | QueryGenerator 字段匹配；排序 create_time desc |

**响应示例**

```json
{
  "success": true, "code": 200,
  "result": { "total": 3, "records": [
    { "id": "a1", "bizType": "approval", "bizId": "ap1", "bizCode": "OA-20261117-001",
      "action": "submit", "fromValue": null, "toValue": "pending",
      "operatorName": "张三", "detail": "步骤数=2, 类别=加班申请",
      "createTime": "2026-11-17 10:00:00" },
    { "id": "a2", "bizType": "approval", "bizId": "ap1", "bizCode": "OA-20261117-001",
      "action": "approve", "fromValue": "step:1", "toValue": "step:2",
      "operatorName": "贺致远", "detail": "同意", "createTime": "2026-11-17 11:00:00" }
  ]}
}
```

## 8. 错误口径

业务错误统一走 `Result.error("上下文文案")`，无 HTTP 状态码语义；全部失败文案带单据 code/id、步骤号、登录人与目标状态等现场信息（见 §4 守卫表）。
