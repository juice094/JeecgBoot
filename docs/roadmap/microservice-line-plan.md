# 微服务线规划与编排（2026-11-18 起草）

> 状态：规划稿，未开工。触发开工须宿拍板（见 §0）。
> 上游：单体在役（8081，jeecg-server-cloud 组件在库未启用）。
> 姊妹篇：`logging-instrumentation-plan.md`（先埋点后拆服务的依赖关系见 §4）。

## 0. 定性：现在不拆，什么时候拆

当前单体对蓝鸥试点是**正确形态**：一个 jar、一个库、本地调用无网络故障面。
拆服务的收益（独立部署/扩容/团队边界）在试点期均为负收益（运维面翻倍）。

**触发条件（满足其一再立项）**：
1. 邮件同步/发送需要独立扩容（I/O 密集型，与审批 API 争线程）且实测成为瓶颈；
2. 出现第二个部署单元诉求（如给客户独立部署邮件网关）；
3. 团队 ≥2 组并行开发同一单体频繁冲突。

未触发前，本线只做**低成本预备**（§2 P0），不真拆。

## 1. 目标架构（届时）

```
            ┌──────────────┐
  客户端 ──▶│ Gateway :9999 │──▶ 路由/鉴权/限流（Sentinel）
            └──────┬───────┘
        ┌──────────┼─────────────┐
        ▼          ▼             ▼
   system-service  team-service  mail-service   （Nacos 注册发现）
   (用户/权限/RBAC) (审批/Issues) (邮箱/发信)
        └──────────┼─────────────┘
                   ▼
        MySQL（按域分库或分 schema，届时再定）
```

天然边界已就位：team / mail 已是独立 Maven 模块（单体 ↔ 微服务只切 `jeecg-system-local-api` ↔ `jeecg-system-cloud-api`，业务代码不动——jeecg 平台能力）。

## 2. 工作包编排

### P0 预备（随时可做，不依赖拆服务，≈1 波）
1. **模块边界体检**：team/mail 模块不得直调 system 内部实现，只能经 `ISysBaseAPI` 等契约接口——全量审查一遍，违规处改为注入契约接口；
2. **无状态化检查**：会话/缓存不落本地内存（jeecg 会话已在 Redis 达标）；MailSyncTracker 的内存态（running 标记）改为 Redis 标志——拆服务后多实例必须外置；
3. **Flyway 治理**：迁移脚本归属按域整理（现状全部挤在 system-start，拆时按服务拆分执行面）。

### P1 首拆 mail（触发后，≈3 波）
mail 最独立（外部协议 I/O、天然网关形态）：pom 切 cloud-api → 独立启动类 → Nacos/Gateway 注册 → 前端 baseURL 按域路由。
- 关键改造：绑定凭据加密密钥（MAIL_CRYPTO_KEY）走配置中心；同步调度器防重入用 Redis 锁。

### P2 team + system（≈2 波）
team 拆出；system 留在最后（权限模型中枢，动它面最大）。

### 全程依赖：日志埋点线（见姊妹篇）
拆服务前的 traceId 贯通与调用面数据是拆分决策依据；拆服务时跨服务 trace 传递（HTTP header 透传）已备好。

## 3. 分布式事务面（提前声明边界）

- 审批通过 → 邮件通知（未来联动）：**最终一致**（本地事务 + 消息/重试表），不用 2PC/seata——试点量级用 jeecg Quartz 或简单重试表即可；
- 写信幂等：SMTP 本身无幂等，靠业务幂等键（SendMailMessageReq.idempotencyKey 字段已预留，本期未实施，拆服务前须落地）；
- 发信日志 system_mail_log 已是独立追踪面（traceId/status/retry），保持。

## 4. 与日志埋点线的依赖

| 依赖 | 说明 |
|---|---|
| 先埋点后拆分 | P0 的 traceId 贯通在单体上做（无跨网络变量），拆服务后只做 header 透传扩展 |
| 数据依据 | 埋点线产出「哪个模块在耗资源、调用链多长」的实证数据，是 §0 触发条件 1 的判定来源 |

## 5. 明确不做

- 不上 K8s/容器编排（试点单机部署形态不变，微服务也只用裸 jar + Nacos）；
- 不拆 jeecg-system 本身的数据库表结构；
- 不引入 seata/消息队列中间件（最终一致用重试表）。
