# 前后端邮件契约差异清单（2026-11-18）

> 执笔：mail-dev
> 对比对象：后端 `jeecg-module-mail` 5 个 Controller 实际实现 vs 前端 `jeecg-team-web/src/api/mail.ts`
> 结论：**路径基本对齐，但 6 处形状/方法不一致 + 6 个端点后端未实现**。前端 `WorkEmail.vue` 当前全 mock，注册后若要接真接口需先按本清单修 `mail.ts`。
>
> **2026-11-18 更新：`mail.ts` 已按后端实际契约重写，D-1~D-6 全部修正，并新增 D-7~D-10。前端页面（WorkEmail.vue）仍为 mock，去 mock 是下一步。**

## 1. 必须修（否则调用必失败）

| # | 位置 | 前端现状 | 后端实际 | 修法 |
|---|---|---|---|---|
| D-1 | `getSystemMailLogStat` | `http.get` | `@PostMapping("/stat")` | 前端改 `http.post` |
| D-2 | `updateMailFolderMapping` | 入参 `{ mapping: [{remoteName, canonical}] }` 数组 | `MailFolderMappingReqDTO` 单条 `{remoteName, canonical}` | 前端改为单条；若需批量，后端加数组 DTO（另案） |
| D-3 | `listMailFolders` | 期望 `{ result: { folders: [...] } }` | `Result<List<OaMailFolderState>>`，result 直接是数组 | 前端去掉 `.folders` 解包 |
| D-4 | `getMailSyncStatus` | `{ lastUid, lastSyncTime, running }` | `{ accountId, running, lastSyncTime, folders: [...] }`，**无 lastUid** | 前端改为从 `folders[].lastUid` 取；或后端在 DTO 加聚合 lastUid（推荐，前端简单） |
| D-5 | 所有 `id` 字段 | `id: number` | `JeecgEntity.id` 为 `java.lang.String` | 前端全量改 `string`；路径参数传 string 无影响 |
| D-6 | `baseURL` | `/jeecg-boot` 经 vite 代理到 **8081** | 冒烟打 **8082** | 冒烟期间改 `vite.config.ts` 代理目标到 8082，或临时改 `http.ts` baseURL |
