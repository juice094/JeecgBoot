# 邮件密码加密方案（D-20261117-76 落地实现）

> 日期：2026-11-17
> 执笔：mail-dev
> 决策：D-20261117-76（宿已拍板）——试点=应用层 AES + 配置密钥；接口按可插拔预留国密/KMS 升级

## 1. 方案要点

| 项 | 口径 |
|---|---|
| 算法 | AES/GCM/NoPadding，256 位密钥，GCM 认证标签 128 位 |
| 密文格式 | `Base64(iv(12字节) ++ cipher)`，每次加密随机 IV，同一明文两次加密密文不同 |
| 密钥来源 | 配置项 `jeecg.mail.crypto.key` 或环境变量 `MAIL_CRYPTO_KEY`（Base64 编码的 32 字节密钥） |
| 密钥缺失 | 构造即抛 `IllegalStateException`（fail-fast），**禁止静默明文落库** |
| 解密失败 | `JeecgBootException` 带上下文（密钥不匹配/密文损坏），不吞异常 |
| 哈希禁令 | SMTP 需原文认证，禁止不可逆哈希（需求文档 §4.4） |

## 2. 代码落点

- 接口：`support/MailPasswordCodec.java`（encode/decode）
- 试点实现：`support/AesMailPasswordCodec.java`（`@ConditionalOnMissingBean`，任何模块提供 `MailPasswordCodec` Bean 即整体替换 → 国密/KMS 升级路径）
- 使用点：
  - `SystemMailAccountServiceImpl.createAccount/updateAccount`：落库前 encode（PUT 密码留空 = 不修改）
  - `SystemMailAccountServiceImpl.testConnection` / `JavaMailDelivery.deliver`：SMTP 认证前 decode

## 3. Phase 2 注册时的配置事项

- `jeecg-system-start` 的 `application-dev.yml`（及对应 profile）增加：

  ```yaml
  jeecg:
    mail:
      crypto:
        key: ${MAIL_CRYPTO_KEY:}   # Base64(32字节)，生产走环境变量/配置中心
  ```

- 密钥生成示例：`openssl rand -base64 32`
- 密钥轮换：旧密文需用旧密钥解密后按新密钥重加密（pilot 无存量数据，首次配置即可）

## 4. 测试

`AesMailPasswordCodecTest` 9 用例：加解密往返、随机 IV（同明文两密文不同）、空值透传、错钥/篡改/非 Base64 均失败带上下文、三类构造参数 fail-fast。
