# 凭证作废与重置指南（2026-11-18）

> 执笔：mail-dev
> 背景：QQ 授权码与 MAIL_CRYPTO_KEY 已出现在对话记录中，按最小暴露原则给出作废/重置步骤。

## 1. 涉及的凭证

| 凭证 | 来源 | 当前状态 | 风险等级 |
|---|---|---|---|
| QQ 邮箱授权码 | 用户在对话中提供 | 已出现在对话记录 | 中：可读邮件、可发信 |
| MAIL_CRYPTO_KEY | 本轮 openssl 生成 | 已出现在对话记录 | 低：当前库无 mail 数据 |

## 2. QQ 邮箱授权码作废与重置

### 2.1 作废旧码

1. 登录 QQ 邮箱网页版。
2. 进入 设置 → 账户 → POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务。
3. 找到 IMAP/SMTP 服务（或 POP3/SMTP 服务）区块。
4. 点击「生成授权码」旁的「管理」，删除或停用旧授权码。
5. 按提示完成验证，确认旧码失效。

### 2.2 生成新码

1. 同一页面点击「生成授权码」。
2. 按提示完成短信/密保验证。
3. 复制新的 16 位授权码。
4. **只在本机 shell 里 export，不要再贴进对话、issue、PR。**

    export QQ_AUTH='新授权码'

### 2.3 验证新码

注册后跑冒烟 §2.5 测连即可验证：

    curl -s -X POST "$BASE/system/accounts/$ACC_ID/test" -H "X-Access-Token: $TOKEN"

预期 result.smtpOk=true。授权码错误返回 errorCode=smtp_auth_failed。

## 3. MAIL_CRYPTO_KEY 重置

### 3.1 何时可重置

- 库中无 mail 数据：可随时重置，无副作用。
- 库中已有加密数据：**不能直接重置**，否则旧密文无法解密。须先解密再重加密，属另案迁移。

当前库无 mail 数据（模块未注册、DDL 未执行），可直接重置。

### 3.2 生成新密钥

    openssl rand -base64 32

### 3.3 生效方式

    export MAIL_CRYPTO_KEY='新密钥'

不写文件、不提交、不留 shell 历史。

### 3.4 已加密数据迁移（仅当库有数据时）

不在本次范围。若后续需要，另案：用旧 key 解密 → 用新 key 加密 → 更新库 → 确认全量迁移后再切换配置。

## 4. 对话记录泄露处置清单

如果这份对话记录会被导出、共享或长期留存，按顺序执行：

1. 作废 QQ 授权码（§2.1），生成新码（§2.2）。
2. 重置 MAIL_CRYPTO_KEY（§3.2）。
3. 检查 shell 历史：

    history | grep -E 'QQ_AUTH|MAIL_CRYPTO_KEY'

   如有命中，删除对应行或 `history -c`。

4. 检查 git 历史与工作区：

    git log --all -p | grep -E 'QQ_AUTH|MAIL_CRYPTO_KEY|pgpvrocdojzbebcg'
    git status

   预期均无结果。

5. 确认工作区无含凭证的文件（尤其 `docs/`、`config/`、`.env*`）。

## 5. 长期纪律

- 凭证只走环境变量或请求体，不落文件。
- 不在 issue/PR/聊天中贴明文。
- 冒烟结束执行：

    unset MAIL_CRYPTO_KEY QQ_AUTH

- 库中密码字段由 AesMailPasswordCodec 加密存储；应用日志不得含明文（需求 D-4 验收项）。
- 授权码泄露窗口内若收到异常登录通知，立即作废并检查邮箱登录记录。

## 6. 已确认的安全事实

- `jeecg-system-start/config/` 已被 `.gitignore:27` 忽略，但该目录不是 Spring Boot 外部配置目录，本次未向其中写任何凭证。
- 凭证传递通道：`MAIL_CRYPTO_KEY` 走环境变量（AesMailPasswordCodec 构造器有 `${MAIL_CRYPTO_KEY:}` fallback），QQ 授权码走请求体。
- 本次未修改任何会被 git 跟踪的文件来存凭证。
