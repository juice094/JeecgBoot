# 邮件线 B-3/B-5/B-6 施工计划书（2026-11-18）

> 目标：闭合员工邮箱最后四刀——详情正文、已读回写、删除、写信，**并补列表分页**（用户指出 /tools/email 缺分页）。
> 前置：索引/同步/绑定/查件已闭环（CLOSURE-WALKTHROUGH-2026-11-18）。本文为唯一施工依据。

## 0. 设计决策

| 决策点 | 方案 | 理由 |
|---|---|---|
| 正文存储 | **实时 FETCH，不落库**（打开详情时按 (account, 文件夹, imapUid) 现抓） | 容量最小、无敏感正文驻留、与 B-2「索引不存正文」口径一致；代价是打开慢一拍，用 fetchLatencyMs 如实上报 |
| 打开详情 | 即视为已读：IMAP `\Seen` 回写 + `read_flag=1` 落库 | Outlook 口径 |
| 删除语义 | 有「已删除」映射 → copy 到 Trash + 源 expunge；无映射 → 直接 expunge（永久删除） | QQ 默认无 Trash 映射时行为明确；Trash 内副本由下次同步按新 UID 入索引 |
| 写信 | 绑定账号 SMTP 直发；发后 best-effort 追加到「已发送」（失败仅告警不阻断） | 复用 ImapSmtpConnector 的握手口径；已发送可见性靠同步游标兜底 |
| 权限码 | 读/已读=`team:mail:message:list`；删除=`team:mail:mailbox:delete`；写信=`team:mail:send`（全部存量码） | 避免动权限表；细粒度新码列为后续可选项 |
| 分页 | 后端 pageMessages 早已支持 pageNo/pageSize；**缺口在前端**（写死 50 条首屏、计数显示 loaded 数） | 前端补 pager：pageSize 20、total 显示、翻页重置选中 |

不做的：正文搜索（B-3 原文档范围外）、附件上传写信（占位）、幂等键去重（接收字段不实施）、to-todo/biz-links/agent 线（封存）。

## 1. 接口契约（前端 mail.ts 既有桩即规格）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /team/mail/messages/{id} | 详情：实时抓正文（text/html 提取 + 附件元数据），顺带已读回写 |
| PATCH | /team/mail/messages/{id}/read {read} | 已读/未读置位（IMAP flag + 索引列） |
| DELETE | /team/mail/messages/{id} | 删除（Trash 映射优先，否则永久） |
| POST | /team/mail/messages/send | 写信（accountId/to/cc/bcc/subject/html） |
