## 1. 依赖排序结论

**账号（§3.1）→ 模板（§3.2）→ 发送（§3.3 补 batch）→ 日志（§3.4）**，理由：

1. **账号先行**：模板 `account_id` 语义引用账号；发送时校验账号启停（A-1）；删除账号需拒绝被引用（§3.1 DELETE 行）。账号不定，模板落库无锚点。
2. **模板次之**：发送已依赖模板（已通）；`preview` 接口零成本——`MailTemplateParser.render` 是纯函数，preview = extractKeys + render，无新依赖。
3. **发送补 batch**：单发闭环已通，batch 是循环 + 单条落日志，无新依赖，可与模板并行。
4. **日志最后但可并行**：查询/重试/stat 的数据由发送产生，接口本身只依赖 SystemMailLog 表与状态机（已就绪）。不阻塞前序，排最后仅为验收叙事顺。
